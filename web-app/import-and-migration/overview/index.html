Import & Migration — Overview

Department menu → Import & Migration

Import & Migration brings the data your department already has into Resgrid: people and their emergency contacts, stations and groups, roles and the certifications they require, certification types and the certifications people hold, unit types, units and their certifications, custom statuses, call types, call priorities, and points of interest with their types. You work from a spreadsheet (CSV, Excel .xlsx, JSON, JSON Lines or GeoJSON), from the Resgrid starter workbook, or from an export of the system you are leaving. Every row is checked and shown to you before anything is saved, every import is journaled so it can be rolled back, and imported people stay dormant — they cannot sign in and receive nothing — until you invite them.

Preview feature

Import & Migration is a Preview feature: it is off by default and Resgrid turns it on per department while it is being rolled out.

## What you can bring

Each kind of data is a data set with a fixed list of fields (its contract). One uploaded CSV file, or one sheet of a workbook, becomes one data set. Data sets are imported in dependency order: stations before the people who belong to them, unit types before the units that use them.

## Where to find it
  • Department menu → Import & Migration (below Subscription & Billing). The item appears only for department administrators, and only when the feature is turned on for your department.
  • Admin Assist → Import & Migration: the button in the toolbar on every Admin Assist tab, and the Import & Migration card beside the review on Setup Report and Admin AI → Overview. See Help & Setup.
  • Setup Wizard → step 1 → Import or migration → Open Import & Migration — the starting point for a new department. See Help & Setup.
  • Directly at /User/DepartmentImport.

The landing page lists your import workspaces (name, what you are doing, status, last activity) with Resume / Open and Cancel, a Start an import panel, a link to these pages and a Settings button (Import & Migration settings). Two banners can appear: File storage for imports is not set up on this system yet (uploads are disabled until the server's import storage is configured) and An import is running for your department right now (you can prepare another workspace, but only one import writes at a time).

A workspace holds everything for one migration: the files, the checked rows, your decisions, the import runs and the support conversation. You can leave and come back at any time; long steps run in the background and keep going if you close the page.

## The journey

The Your progress list on the Overview tab follows these steps. Steps 3–6 repeat for each data set, and you can import in waves — for example stations and roles first, check them in Resgrid, then come back for people.

#StepYouResgrid
1StartStart a workspace and choose what you are doing.Creates the workspace.
2Get your filesDownload the starter workbook or export from your current system, then upload.Uploads in pieces, scans the file, splits workbooks into data sets and works out what each one contains (details).
3Match columns and valuesConfirm what each file contains, which column fills which field, and how codes in your file map to Resgrid options (details). Skipped for the starter workbook.Re-checks after every change.
4Fix issuesWork through grouped issues: accept a warning, exclude rows, set a value, or fix the file and upload it again (details).Runs the verification ladder.
4aConfigure ResgridDescribe your department, then accept, change or decline the settings the import will change: names, modules, numbering and more (details).Suggests values from your operating profile and your data; changes nothing until you approve.

6ImportWatch progress on the History tab, or leave. You can pause or cancel between chunks.Changes the accepted settings first, then writes in dependency order, in small chunks, journaling every change.

8Activate & inviteConfirm administrators, invite people, sign off (details).Sends invitations in small batches outside night hours.

Within one workspace, a row that was already imported is recognized by its Source ID when you upload a corrected file again, so it is not added twice. A new workspace recognizes an earlier workspace's Source IDs only when you say it continues that import on its Files tab — do that first when you choose Continue an earlier import. Otherwise, rows are matched to existing records by name (people by email) — see the matching rules on each field reference page.

## Safety principles
  • Nothing is saved before you approve it. Uploading, matching and fixing only change the workspace. Records are written only by an import you approved on Review & import, and only for the data sets you ticked.
  • Imported people are dormant. They cannot sign in, password reset is refused, and they receive no dispatches, messages, reminders or digests until you invite them. Nobody is emailed during an import — not even a welcome email. See Dormant members.
  • Existing data is not overwritten by default. Add only never changes what is already in Resgrid; Review updates changes only fields of matched records, skips anything someone edited after the preview, and never touches a person's own profile (name, phone numbers, language).
  • Every import can be rolled back within its window. Records the import created are removed, changed records get their earlier values back, and anything used since stays for you to check by hand. See Rollback.
  • One import writes at a time. An import holds a department lock that keeps a second import, an Advanced Data Protection migration and department deletion out — but your department keeps working normally while it runs.
  • Resgrid support sees only what you choose to share, for as long as you choose, and every staff action is on your timeline. See Getting help from support.
  • Sensitive data stays out of your department's records. Columns that look like passwords, ID numbers, card numbers, dates of birth or medical data are left out when the file is read: their values are never checked, held as workspace data, shown on screen or imported. The file you uploaded still contains them — it is stored encrypted and deleted on a schedule, so take those columns out of the export before you upload it.
## Not in this release
  • Configuration presets (setting Resgrid up from your operating profile) and historical data (closed calls, training history, Records) are not part of this release.
  • Product packs that recognize a specific vendor's export automatically are planned for later releases; until a pack is published, every file other than the Resgrid starter workbook goes through column matching, which works for any spreadsheet.
  • ZIP packages, KML, KMZ and GPX files are recognized but not imported yet.
## Notices you receive

The administrator who started the workspace (or, if they are no longer an administrator, the first active administrator) gets a notification when an import or rollback finishes, fails, pauses or waits for a decision; when Resgrid support posts a message, a suggestion or a status change; and after 30 days without activity. Notices name the outcome and link to the workspace — they never contain imported data. Each administrator receives them in the language set on their own profile (English when none is set).

Admin Assist also follows imports: Setup Report counts the area as complete once an import has been verified, and findings appear when an import has been stuck on blocking issues for over a week, finished with unexplained differences, left imported people uninvited for over two weeks, or kept files longer than usual.
