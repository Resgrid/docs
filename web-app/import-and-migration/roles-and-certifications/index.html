Roles and Certifications — Field Reference

Department menu → Import & Migration → (workspace) → Files & data sets

Three data sets cover what people do and what they are qualified for: Roles (Engineer, Paramedic, Officer …), Certification types (the certifications that exist — Firefighter I, EMT, CPR …) and People's certifications (which person holds which certification, with numbers and dates). Roles and certification types come before people; people's certifications come after them.

Preview feature

Import & Migration is a Preview feature: it is off by default and Resgrid turns it on per department while it is being rolled out.

## Where to find it

Fill in the Roles, Certification types and People's certifications sheets of the starter workbook (or resgrid-roles.csv, resgrid-certification-types.csv, resgrid-personnel-certifications.csv), or upload your own lists and match them on the matching page. Download current data exports your existing roles and certification types.

After the import, roles are on the Personnel screen and certifications in Certifications and Types.

## Turning it on

Part of Import & Migration: the Onboarding.MigrationWizard flag on for your department and a department administrator signed in. See Overview → Turning it on.

## Role requirements sheet

Which certifications each role requires. A role's other requirements stay as they are. If your department enforces requirements, people lacking one can lose the role at the next nightly check.

Starter workbook sheet Role requirements; CSV template resgrid-role-requirements.csv; imported after Roles, Certification types.

Column headerField keyTypeRequiredNotes
Role [role]roleReferenceYesWhich role, by its name or source ID. Refers to Roles. Example: Engineer. Headers recognized: role, position, role name.
Required certification [certification_type]certification_typeReferenceYesWhich certification the role requires, by its name, code or source ID. It must be a type people hold. Refers to Certification types. Example: Driver/Operator. Headers recognized: certification, certification type, required certification, qualification.
Mandatory [mandatory]mandatoryYes/NoYes when the role cannot be held without it (the default); no for a recommended certification. Example: yes. Headers recognized: mandatory, required, is required.
Any-of group [any_of_group]any_of_groupWhole numberRequirements of one role with the same number are alternatives: holding any one of them is enough. From 1 to 99. Example: 1. Headers recognized: any of group, group, one of group, alternative group.
Trainee allowed [allow_trainee]allow_traineeYes/NoYes when someone still training for the certification may hold the role. Example: no. Headers recognized: allow trainee, trainee allowed, trainee.
Grace days [grace_days]grace_daysWhole numberDays a person keeps the role after the certification lapses, instead of the department's default. From 0 to 3650. Example: 30. Headers recognized: grace days, grace period, grace.

Contract role-requirements version 2026.11.1, generated from the import catalog.

One row is one role and one certification type. A role's other requirements stay as they are; a row for a role and type that already have a requirement is matched to it (and, with Review updates, its options are changed). Rows with the same Any-of group number for a role are alternatives. The type must be one people hold (N role requirements use a type meant for units). If your department enforces role requirements (certification settings, mode Enforce), the preview asks you to confirm that people lacking a newly required certification can lose the role at the next nightly check. Rolling the import back removes the requirements it added and puts back the options it changed.

## How rows are matched
Data setMatched to existing records by
RolesSource ID (same workspace, or the import it continues), otherwise name — ignoring case, accents, spaces and punctuation. Two existing roles with the same name block the row.
Certification typesSource ID (same workspace, or the import it continues), otherwise name.
People's certificationsNever matched to certifications already in Resgrid — the same person can hold two records of one certification. Within a workspace, a row already imported (same person, certification and certificate number) is recognized and not added again; in a different workspace it would be added again, so import each person's certifications once.

More rules:

  • Person refers to a person by their Source ID or email — a row in your People file or an existing member. It must point at a person; Keep as text is not possible here.
  • Certification refers to a certification type by its name, code or Source ID. The type must be one that people hold — a type for units fails the row (certifications use a type meant for units).
  • Expires on must not be before Issued on.
  • Certifications that have already expired are imported marked Expired, and nobody is emailed. Certifications expiring soon get no reminders while the holder is dormant. Both are statements you confirm before approving.
  • A person's roles that require certifications are retried at the end of the import, after the certifications are written — approve People and People's certifications in the same import so certification requirements do not leave those roles out.
  • Certificate number is protected by Advanced Data Protection when your department uses it. Area and Issued by are not: they describe the qualification, and qualification-based dispatch reads them.
  • On the value matching page, unknown roles and certification types can be created new with just their name.
